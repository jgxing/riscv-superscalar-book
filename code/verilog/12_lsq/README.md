# 第 12 章 乱序访存 LSQ 代码

## 文件

- `lsq.v`：八项访存队列。记录每条访存的地址、数据和年龄，做 store-to-load 转发，检测 load 投机违例。
- `tb_lsq.v`：自测程序，20 项检查全过。

## 接口怎么读

接口按"一条访存走过 LSQ 的过程"分成四组。

| 组 | 信号 | 含义 |
|---|---|---|
| 入队 | `alloc_en_i`, `alloc_is_store_i`, `alloc_age_i`, `alloc_dest_i` | 进一条访存 uop，带年龄和目的物理号 |
| store | `st_addr_en_i/idx_i/addr_i`, `st_data_en_i/idx_i/data_i` | 地址和数据分别就绪，不必同拍 |
| load | `ld_en_i`, `ld_idx_i`, `ld_addr_i` | 地址算完，请求投机读 |
| 输出 | `ld_fwd_hit_o`, `ld_fwd_data_o`, `ld_addr_o`, `ld_dest_o` | 转发命中给数据，未命中给访存地址 |
| 违例 | `violation_o`, `violation_age_o` | 发现更老的 store 与已投机的 load 同址 |

`idx_i` 是表项编号，位宽由 `IDX_W` 给出。`busy_o` 是一位热，表示哪些项还占着。

## 三个关键落点

1. **地址和数据分开就绪**。store 的地址由 AGU 算，数据可能来自重命名后的源操作数，两者不一定同拍到齐。只有两者都就绪的 store 才能参与转发。
2. **转发取最年轻的更老 store**。检查所有比 load 老、地址相同、数据已就绪的 store，取其中年龄最大的那个，因为它是程序顺序上最近的一次写。代码里用 `!fwd_hit || (age[e] > best_age)` 保证第一项无条件入选，后续再比较年龄。
3. **违例靠事后比对**。load 可以不等更老的 store 算完地址就投机读；等那个 store 地址出来，若发现同址且 load 已经读过，就报违例，让 load 重做。正确性由检测兜底，不必一开始就保守等待。

## 两个坑

- 找"年龄最大的命中项"时，`best_age` 的初值不能设成全 1。年龄是正数，全 1 是最大值，`age[e] > best_age` 永远不成立，转发永远不命中。初值设 0，并配合 `!fwd_hit` 让第一个命中项无条件入选。这个错误的症状是违例检测全对、转发全挂。
- 索引位宽要用 `$clog2(ENTRY)` 这样的对数宽度（`IDX_W=3`），不是 `ENTRY` 本身。写成 `[ENTRY-1:0]` 虽然能零扩展跑通，但端口语义错了：那是 8 项队列的编号，不是 8 位宽的编号。

## 已知简化

- 没有真正的内存或缓存模型。转发未命中时只输出地址，读写内存留给下一级。
- store 没有提交逻辑。真实机器要等 store 提交才写内存，这样预测错误时不会污染内存；这里只做到"进 LSQ 等转发"。
- 没有 TLB、缓存一致性或 RVWMO 的形式化模型。正文只讲为什么需要访存规则。
- 队列满时直接拒绝入队，不拉背压。教学核先把顺序记账讲清楚。

## 运行

```bash
iverilog -g2012 -o sim.vvp *.v
vvp sim.vvp
```

应看到 `ALL TESTS PASSED`。测试覆盖：复位、入队、同址转发、目的号与地址透传、地址未算出不转发、投机违例、地址不同不报违例、更年轻的 store 不转发、两个更老 store 取最近、数据未就绪不转发、队列满时拒绝。
