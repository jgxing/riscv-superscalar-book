# 第 5 章 分支预测配套代码

这一章实现分支预测器的两个核心部件，都是教材里"先看接口、再看实现"讲过的模块。

## 文件

| 文件 | 内容 |
|---|---|
| `bht.v` | 分支历史表。每个表项一个 2 位饱和计数器，PC 低位索引，taken 加一、not taken 减一，两端饱和。最高位给预测方向。 |
| `btb.v` | 分支目标缓冲。直接映射表，PC 中间位索引，表项存有效位、标签、目标地址。有效且标签匹配才算命中。 |
| `tb_branch.v` | 自测台，覆盖饱和、方向翻转、复位、BTB 命中与标签失配。 |

## 运行

需要 Icarus Verilog。在本目录下执行：

```bash
iverilog -g2012 -o sim.vvp bht.v btb.v tb_branch.v
vvp sim.vvp
```

预期输出 `ALL TESTS PASSED`，共 16 项检查。

## 几个观察点

1. **饱和**。计数器到 11 再收到 taken、到 00 再收到 not taken，状态都不再变。这就是它比 1 位预测器稳的原因。
2. **方向在 10 就翻转**。状态 10（弱跳）的最高位是 1，预测已经是"跳"。弱状态承担的是"刚出现过一次相反结果、但还没改口"的过渡角色。
3. **复位成 01**。弱不跳起步，比强不跳保守，多数程序首次遇到某分支时不跳的概率更高。
4. **BTB 标签**。索引只取 PC 中间位，不同分支会撞到同一项，标签用来认人。testbench 里专门构造了"索引相同、标签不同"的情形，验证不会误报命中。

## 教学的边界

这两个模块刻意做了简化：BHT 用 PC 低位直接索引，没有引入全局历史；BTB 是直接映射，没有组相联，也没有 ITTAGE 处理间接跳转。真实处理器在这些地方要复杂得多。本章的目标是让读者看懂"方向预测"和"目标预测"两件事分别是怎么做的，以及 2 位计数器为什么有效。TAGE、SC 等只在教材正文里讲思想，不作实现要求。
