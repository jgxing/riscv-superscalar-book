# 第 11 章 执行单元与旁路代码

## 文件

- `bypass.v`：旁路选择器。把两个源物理号同旁路结果的目的号做内容比较，命中就改用旁路值。
- `alu.v`：单周期整数 ALU，支持加、减、与、或、异或、左移、小于置一。
- `exec_unit.v`：一个整数执行口。先旁路选源，再送 ALU 运算，结果连同目的号寄存下来供广播。
- `tb_execute.v`：自测程序，18 项检查全过。

## 接口怎么读

接口分三组，正好是三级搭起来的。

| 组 | 信号 | 含义 |
|---|---|---|
| 旁路输入 | `ps1_i`, `ps2_i`, `rdata1_i`, `rdata2_i` | 源物理号与寄存器堆读出的值 |
| 旁路结果 | `byp_en_i`, `byp_dest_i0/1`, `byp_data_i0/1` | 本拍哪几路结果可用，各自写哪个物理号、值是多少 |
| 执行口 | `valid_i`, `op_i`, `dest_i`, `result_o`, `dest_o`, `out_valid_o` | 进来一条 uop，出去一个带目的号的结果 |

`byp_en_i` 每位对应一路结果，`byp_en_i[1]` 是更晚产生的那一路。两路目的号撞车时，代码里写在后面的第 1 路覆盖第 0 路，这对应真实机器里"最新结果优先"。

## 三个关键落点

1. **旁路靠内容比较**：拿源物理号同结果目的号比，相等说明寄存器堆里的值已经过时，要改用旁路值。和发射队列的唤醒是同一招，只是唤醒置的是就绪位，这里选的是数据。
2. **比较只是一半**：命中与否还受 `byp_en_i` 控制。功能部件没真正算出结果之前，目的号不能挂到旁路网上，否则消费者会拿到错误数据。多周期部件尤其要注意这一点。
3. **时序约定**：旁路选择是组合逻辑，时钟沿把运算结果、目的号和有效位一起锁存。这意味着本拍旁路进来的值，是上一拍沿已经锁存、现在挂在总线上的结果；本拍算出的结果要到下一拍才对外可用。

## 一个坑

写测试台的 `drive` 任务时，两路旁路的目的号和值要按 `bd0, bv0, bd1, bv1` 的顺序交错声明。如果顺手写成 `bd0, bd1, bv0, bv1`，任务调用时传进去的 `bv0` 会被当成 6 位的目的号截断，值变成 0，于是所有"旁路命中"的用例都失败，而"未命中"的用例反而全过。这个现象很有迷惑性，看起来像旁路比较逻辑坏了，其实是测试台自己的参数顺序错了。

## 已知简化

- ALU 是单周期的，没有做乘法、除法的多周期或流水化版本。正文用图讲它们与旁路的关系，代码只保留最短的闭环。
- 只有两路旁路结果，对应两发射核的两个执行口。真实机器执行端口更多，旁路网也更复杂。
- 没有实现寄存器堆本体，读出的值直接由测试台给出。旁路要解决的正是"读出来的值可能已经过时"这件事。
- 没有处理地址生成和访存结果的旁路，那是第 12 章的内容。

## 运行

```bash
iverilog -g2012 -o sim.vvp *.v
vvp sim.vvp
```

应看到 `ALL TESTS PASSED`。测试覆盖：复位、源 1 命中、目的号不符、旁路未使能、源 2 命中、两路分别命中、两路撞车时新的优先、单路有效、减法与逻辑运算走旁路、左移与比较、目的号透传、空泡传播。
