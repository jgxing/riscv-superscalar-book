# 第 14 章 重定向与状态恢复代码

## 文件

- `checkpoint.v`：检查点缓冲。分支重命名时拍下 RAT 和空闲表指针的快照，预测错误时按编号读出，分支退休后释放。
- `recover.v`：重定向控制。两路来源选一个，发前端重定向、后端 kill 掩码和状态恢复数据。
- `tb_recover.v`：自测程序，17 项检查全过。

## 检查点存什么

一个检查点存四样东西。

| 字段 | 作用 |
|---|---|
| `valid` | 这个槽是否还有效 |
| `rat_snap` | 整张 RAT 的快照，32 项各 6 位 |
| `fl_head_s` / `fl_tail_s` | 空闲表的头尾指针 |
| `seq_snap` | 拍快照那条分支的序号，debug 和排序用 |

存整张表最省事，代价是每个在飞分支都占 32×6 位。真实处理器常用增量记录，只存这条分支之后被改过哪几项，恢复时只回退那几项。本书选整表快照，为的是把恢复这件事讲清楚。

## 接口怎么读

两路重定向来源。

| 来源 | 信号 | 含义 |
|---|---|---|
| 分支错 | `br_mispred_i`, `br_pc_i`, `br_seq_i`, `br_cp_i` | 分支执行单元发现猜错，给出正确 PC、分支序号、检查点号 |
| 异常 | `exc_i`, `exc_pc_i`, `exc_seq_i`, `exc_cp_i` | 提交口发现异常，给出处理入口 PC |

输出分三组。

| 组 | 信号 | 含义 |
|---|---|---|
| 前端 | `front_redirect_o`, `front_pc_o` | 让前端从正确 PC 重新取指 |
| 后端 | `back_flush_o`, `kill_from_o`, `kill_mask_o` | 冲刷阈值与逐项 kill 掩码 |
| 恢复 | `restore_en_o`, `restore_rat_o`, `restore_fl_head_o`, `restore_fl_tail_o` | 恢复到检查点的 RAT 与空闲表指针 |

`kill_mask_o` 是对一组在飞 uop 序号 `uop_seq_i` 的逐项判定。序号不小于出错序号的置 1，表示落在错误路径上。真实设计里各队列各自做这个比较，这里集中做一个样例，方便观察。

## 四个关键落点

1. **快照对应分支刚进来的时刻**。RAT 快照在分支重命名那一拍拍下，此时错误路径上的指令还没进来。恢复它就是回到分支的起点。
2. **异常优先于分支错**。两路同时到来时提交口的异常优先。真实设计里两者都要按程序顺序排队处理，这里用简单优先级表达"必须马上处理"的意思。
3. **kill 按序号不按时间**。序号反映程序顺序，出错那条及其之后的全部冲掉。这保证错误路径上的痕迹被清干净，出错指令本身也不算数。
4. **空闲表指针一起恢复**。错误路径上分配的物理寄存器，靠恢复头尾指针一次性退回池子，不必逐个回收。

## 三个坑

- **组合信号要在时钟沿前读**。`save_id_o` 由组合逻辑找空槽得到，时钟沿一过快照就写进去了，`save_id_o` 随即指向下一个空槽。测试台必须在拉高 `save_en_i` 之后、时钟沿之前读它。
- **恢复编号来自仲裁结果**。检查点的 `restore_id_i` 接的是选中那路来源的检查点号，不是某路输入端口。没有重定向请求时改 `br_cp_i` 不会影响恢复输出。
- **kill 掩码包含出错指令本身**。判据是 `>=` 而不是 `>`。出错那条也得作废，否则它的错误结果会留下来。测试里序号 9 出错时，9 到 13 这五条全部 kill，掩码是 `8'b11111000`。

## 已知简化

- 恢复输出是组合的，一拍内完成。真实机器里恢复 RAT、冲刷各队列、重定向前端往往分几拍流水做，这里不追时序。
- 检查点满时 `save_full_o` 拉高，但重命名侧如何拉背压没有实现，只留信号。
- 异常恢复和分支错恢复走同一套检查点逻辑。真实设计里异常常走 ROB 逐项回退，因为异常可能发生在没有检查点的指令上。这里统一处理，只讲思想。

## 运行

```bash
iverilog -g2012 -o sim.vvp *.v
vvp sim.vvp
```

应看到 `ALL TESTS PASSED`，错误数为 0。测试覆盖：复位、两次拍快照拿到槽号、按编号恢复 RAT 与空闲表指针、分支错重定向、kill 掩码、异常优先、释放后槽位复用、检查点写满。
