# 第 4 章配套代码  FTQ 取指目标队列

一个简化但能真正跑起来的取指目标队列（FIFO），对应教材 4.4 节和 4.8 节。

## 文件

| 文件 | 内容 |
|---|---|
| `ftq.v` | FTQ 模块：存地址的同步 FIFO，深度 8、地址宽 32 位，可参数化 |
| `tb_ftq.v` | 自测文件，覆盖复位、写至满、满时拒写、读至空、读写同拍 |
| `sim.vvp` | 仿真产物（运行后生成，可忽略） |

## 运行

需要 Icarus Verilog（iverilog / vvp）：

```bash
iverilog -g2012 -o sim.vvp ftq.v tb_ftq.v
vvp sim.vvp
```

全部测试通过时，最后一行输出 `ALL TESTS PASSED`。

## 设计要点

- **存的是地址，不是指令**。预测器从 `push` 口写入后续取指地址，取指从 `pop` 口读出，地址经 `pop_addr` 送出。
- **多一位指针判满判空**。深度 8 用 4 位指针：最高位只服务于判满，空是 `head == tail`，满是"最高位不同、其余位相同"。
- **索引要取低位**。访问 `ftq_mem` 时用 `tail[PTR_W-2:0]` / `head[PTR_W-2:0]`。若直接用完整指针，写满时指针到 8 会越过数组边界，读出 `x`——这是实际调试时踩过的坑，教材里也写了。
- **读写同拍互不影响**。预测侧写队尾、取指侧读队头，同一拍各走各的指针，队列深度保持不变。

## 已知的工具限制

这个版本的 Icarus Verilog 有几个保留字/语法限制，代码里已经避开：

- `table` 不能用作存储器名（用 `ftq_mem`）；`expect` 不能用作 testbench 信号名（用 `exp_addr`）。
- 存储器上界不能直接写参数表达式 `[0:DEPTH-1]`，先转成 `localparam DEPTH_M1` 再写。
