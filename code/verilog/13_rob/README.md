# 第 13 章 重排序缓冲 ROB 与提交控制代码

## 文件

- `rob.v`：八项环形队列。按程序顺序分配、乱序登记写回、按序提交，支持精确异常重定向。
- `tb_rob.v`：自测程序，17 项检查全过。

## ROB 表项存什么

每项记六样东西。

| 字段 | 作用 |
|---|---|
| `valid` | 这一项是否被占用 |
| `done` | 执行是否已写回（乱序置位） |
| `except` | 这条 uop 是否带异常 |
| `pc` | 指令地址，异常重定向时要用 |
| `dest` | 目的物理寄存器号（教学骨架只登记，不在这里写回） |
| `old_pd` | 被覆盖的旧物理号，提交时释放给空闲表 |

真实 ROB 还会记 uop 类型、是否 store、异常向量等。骨架只留讲清楚提交和异常所需的最小集合。

## 接口怎么读

接口分四组。

| 组 | 信号 | 含义 |
|---|---|---|
| 分配 | `alloc_en_i`, `alloc_pc_i`, `alloc_dest_i`, `alloc_old_pd_i` | 重命名阶段按程序顺序写入 |
| 写回 | `complete_en_i`, `complete_idx_i`, `complete_except_i` | 执行完成时按索引登记，可带异常 |
| 提交 | `commit_cnt_o`, `commit_pc_o`, `commit_free0_o`, `commit_free1_o` | 本拍提交几条、第一条 PC、释放的旧物理号 |
| 异常 | `redirect_en_o`, `redirect_pc_o` | 队头异常时给出重定向目标 |
| 观察 | `full_o`, `empty_o` | 队列满 / 空 |

`complete_idx_i` 是 ROB 索引，不是物理寄存器号。执行单元写回时要带上自己分配到的 ROB 索引，才能找到对应表项打上完成标记。

## 三个关键落点

1. **写回乱序，提交按序**。`complete` 可以命中任意表项置 `done`；提交永远从 `head` 开始，只认连续 `done` 的项。队头没完成，后面全完成也得等着。
2. **精确异常靠按序提交兜底**。异常项之前的正常项先提交，异常项到队头时触发重定向、清空整个 ROB。于是"异常之前全部生效、异常及之后全部撤销"自然成立，不需要额外的撤销逻辑。
3. **释放 old_pd 接回重命名**。提交时把 `old_pd` 送出去，外部把它还给第 9 章的空闲表。物理寄存器要等到覆盖它的那条 uop 提交才能回收，这一点在重命名章就埋下了伏笔。

## 三个坑

- **异常项之前的项要先提交**。提交窗口里如果第 0 项是正常、第 1 项带异常，本拍应提交第 0 项、在异常项停下，下一拍异常项到队头再重定向。若一遇到窗口内的异常就把整批连坐撤销，会破坏精确异常语义。代码里用 `if (cmt_cnt == 0)` 判断异常项是否已在队头。
- **分配写在提交之后**。`valid` 的分配赋值放在 always 块末尾，避免提交清空和同拍入队互相打架。这个坑和第 10 章发射队列同源。
- **环形索引用低位加法**。`cmt_idx = head[PTR_W-2:0] + j`，靠三位自然回绕实现环形。`head`/`tail` 的最高位只用于判满，不参与索引。

## 已知简化

- `commit_pc_o` 只给本拍提交的第一条 PC，第二条不单独输出；`commit_free0/1` 固定两位，与 `COMMIT_W=2` 绑定。改成别的提交宽度要同步调整这几个端口。
- 重定向直接在异常那拍清空整个 ROB。真实设计会逐项 walk 回收资源、把异常之后的 uop 重新入队，这些放到第 14 章讲恢复时说明。
- store 真正写内存也在提交时做，骨架没有实现，只保留动机。
