# 第 9 章 寄存器重命名代码

## 文件

- `rat.v`：两宽重命名表。32 个逻辑寄存器映射到 6 位物理寄存器号，复位后 Ri 对应 Pi，写 x0 被挡住。
- `free_list.v`：空闲物理寄存器池。深度 32 的循环队列，复位时装入 P32 到 P63，支持一拍分配两个、回收两个。
- `rename.v`：把上面两块接起来的重命名站，附带空闲数不足时的背压信号。
- `tb_rename.v`：自测程序，27 项检查全过。

## 端口怎么读

重命名站的接口可以分三组看。

| 组 | 信号 | 含义 |
|---|---|---|
| 进来 | `wen_i`, `rd_idx_i*`, `rs1_idx_i*`, `rs2_idx_i*` | 两条 uop 改哪个逻辑寄存器、读哪些逻辑寄存器 |
| 出去 | `pd_o*`, `ps*_o*`, `old_pd_o*` | 分配到的物理号、改名后的源、被覆盖的旧映射 |
| 回收 | `free_en_i`, `free_i*` | 来自 ROB 的提交回收，第 13 章接上 |

`*` 表示 0 和 1 两条。`wen_i` 是两位分别是两条 uop 的写使能；`free_en_i` 也是两位，但它是逐位使能，`2'b11` 表示回收两个，不是数值 3。这一点在 `free_list.v` 里专门处理过：指针更新要按位数相加，不能把两位直接当加数。

## 三个关键落点

1. **WAW 化解**：`rat_ram[rd] <= new_pd` 按组顺序更新。同一组两条都写同一个逻辑寄存器时，后一条的赋值写在后面，最终生效。
2. **WAR 化解**：读源操作数时查 RAT 拿到的是"此刻最新的物理号"，之后别的 uop 再改映射，不会改写已经取走的编号。
3. **组内旁路**：`lookup()` 函数让第二条 uop 在第一条刚写完同一逻辑寄存器时，立刻拿到第一条的新物理号，不用等下一拍。同组有真相关时，这是必需的。

`old_pd_o*` 输出的是覆盖前的旧映射，它随 uop 一起写进 ROB。只有提交那条 uop 时才能把这个旧物理寄存器还给空闲表——提前回收会让还在执行的指令读错地方。

## 两个坑

- 多一位指针判满时，索引存储器只能用低位 `head[PTR_W-2:0]`。写满后完整指针会越过数组边界，读出 x。
- 分配两个时，第二个物理号的偏移取 `alloc_i[1]`。因为 `alloc_i` 是数量 2，写成 `alloc_i[0]` 会取到 0，两个 uop 拿到同一个物理寄存器。
