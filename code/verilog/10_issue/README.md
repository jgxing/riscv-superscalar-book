# 第 10 章 发射队列与仲裁器代码

## 文件

- `arbiter.v`：从 N 个请求里挑最多两个，按年龄从小到大发授权。
- `issue_queue.v`：四项发射队列。存物理源号、就绪位和年龄，监听广播置就绪，再把就绪项送出去。
- `tb_issue.v`：自测程序，17 项检查全过。

## uop 打包格式（32 位）

| 字段 | 位 | 含义 |
|---|---|---|
| type | [31:30] | 执行单元类型，教学模型暂不参与选择 |
| rdy1 | [29] | 源 1 是否已就绪 |
| rdy2 | [28] | 源 2 是否已就绪 |
| ps1 | [27:22] | 源 1 的物理寄存器号 |
| ps2 | [21:16] | 源 2 的物理寄存器号 |
| dest | [15:10] | 目的物理寄存器号 |
| age | [9:2] | 年龄，数越小越老 |
| 保留 | [1:0] | 未使用 |

测试里用 `mk()` 函数打包。本章不关心具体运算，只关心"两个源是否就绪"和"谁更老"。

## 接口怎么读

发射队列的接口分四组。

| 组 | 信号 | 含义 |
|---|---|---|
| 进队 | `alloc_en_i`, `alloc_slot_i*`, `alloc_uop_i*` | 本拍进几条、放到哪几项、放什么内容 |
| 唤醒 | `wakeup_en_i`, `wakeup_pd_i*` | 本拍广播了哪些物理寄存器号 |
| 出队 | `unit_free_i`, `grant*_o`, `issue_uop_o*` | 有几个空发射口、选中了哪些项、送出去的 uop |
| 观察 | `busy_o` | 哪些项还占着 |

`alloc_slot_i*` 是一位热的，用第几项由外部决定。教学核这样写是为了把分配和选择分开讲，真实设计会让队列自己找空项。

## 三个关键落点

1. **唤醒靠内容比较**：每拍把广播的物理号同每一项的两个源号比较，命中就把对应就绪位置一。这正是第 3 章 CDB 监听在现代发射队列里的样子。
2. **选择按年龄**：`arbiter.v` 比较的是 `age_i`，不是表项编号。编号小的项不一定更老，直接按编号给优先级会破坏程序顺序上的公平。
3. **唤醒和选择合在一拍**：广播在时钟沿置就绪，同一拍组合逻辑就算出授权，下一拍指令就能进执行单元。这就是背靠背依赖少一个气泡的原因。

## 两个坑

- 分配和发射写在同一组非阻塞赋值里时，分配要写在发射清空之后，否则刚进来的项会被同一拍又选出去。代码里特意把分配放在循环末尾。
- 完全就绪的项只要发射口允许，就会在每个时钟沿被送走。测试里分配那几拍先把 `unit_free_i` 置零，等观察完授权再放开，避免队列在分配的同拍就悄悄出队。

## 已知简化

- 没有实现集中式与分布式发射队列的区别，也没有端口数随发射宽度增长的讨论。
- 入队时空项由测试指定，队列自己不找空位；满时也不拉背压。这些留给完整后端控制一起考虑。
- 仲裁器按年龄选，但年龄相同的两项仍可能按编号顺序打破平局。教学模型不处理并列异常。

## 运行

```bash
iverilog -g2012 -o sim.vvp *.v
vvp sim.vvp
```

应看到 `ALL TESTS PASSED`，错误数为 0。测试覆盖：复位、按年龄单选、双口双选、发射出队、广播唤醒、无发射口时阻塞、两路广播同拍唤醒、单请求时第二授权为空。
